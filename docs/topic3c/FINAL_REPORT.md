# 面向长编程任务的记忆检索自优化：方案介绍与测试结论

题目三 · 方向 C｜2026-09-14 提交版


## 一、问题与研究目标

TencentDB-Agent-Memory 提供 L0 对话、L1 原子记忆、L2 场景和 L3 画像，以及检索、抽取和注入能力。本方案关注基座之上的检索决策：哪些查询可以减少返回条数，哪些查询需要补充原始证据，以及如何根据后续质量反馈更新选择规则。

目标是在控制记忆上下文成本的同时保持答案与任务质量。方案不重写 FTS5、向量检索或抽取模型内核。公开长对话实验用于验证方法，公开编程任务用于检查接口和失败机制，两者均不替代真实多轮长编程业务验证。

## 二、方案设计与实现范围

### 2.1 有界候选动作

实现层提供 Top-10、Top-8、Top-5，以及 Top-5 加最多两条 L0 辅助检索结果。Top-10 是实验比较锚点。L0 动作复用现有全文检索能力，为被裁剪的 L1 结果补充原始上下文。

离线研究还比较了 KNN24、置信约束、规则、ridge、MLP、离线 Q 和场景/邻接组织。生产策略采用 mean/LinUCB，冻结研究采用 KNN；二者动作空间和学习规则并不完全相同，不能把某个离线算法的指标直接归给生产实现。

### 2.2 用受控反馈更新策略

策略使用查询长度、时间和代码线索、文件/函数线索、依赖变化、堆栈和过时风险等特征。反馈包含候选动作和 Top-10 的配对质量与 token 成本；质量与成本分别记录，再用于决策。召回反馈为独立可选信号。

编程适配层把编译、测试、任务结果、回归、过时证据与重试等信息转为质量反馈。配对实验需要调用者保证任务、模型、输入和验证条件一致。策略选择器本身无需额外 LLM 调用，但获取反馈、抽取记忆和运行 Agent 的成本并非免费。奖励采用 reward = (quality_action - quality_top10) + λ × (1 - tokens_action / tokens_top10)。mean 使用作用域与上下文统计排序；LinUCB 在候选通过质量约束后，用预测奖励加不确定性项选择动作，λ 与探索系数均可配置。

### 2.3 晋升与回退

晋升组件默认要求 24 条观测、至少 20 条编程反馈、编程占比至少 80%、token 节省置信下界至少 10%，并检查质量置信下界和回退率。重复 taskId 在当前窗口内拒绝计数；晋升后质量门失效或硬失败会降级，显式 shadow 配置仍优先。合成回放验证了达到门槛后晋升、硬回归后降级。真实反馈采集和人工晋升由适配层接入，插件不会凭空生成独立任务标签。

自动召回入口已接入项目晋升门，每次调用重新读取已持久化的晋升状态。关闭 adaptive 时使用原始静态配置；开启但未晋升时使用 Top-10。L0 不可用、检索异常或超时时，禁用自适应并重试原始基座配置；若基座仍失败则返回结构化错误。每次尝试均受原 recall timeout 约束，发生回退时总等待上限为两次 timeout，已经发出的底层请求不会被强制取消。

### 2.4 编程任务适配

编程实验工具支持受限的搜索、读取、编辑、复现和测试循环。改进重点包括遵循目标运行环境、先验证公开复现、避免循环构造预期答案、读取关联定义与调用位置、执行窄回归，以及将失败带回下一轮。

这些措施缓解了上下文缺失、错误 API 假设和验证协议问题。关联源码证据与自由文本函数摘要卡不同；本报告不主张自由文本卡片已获得稳定收益。

## 三、评测协议与指标

公开长对话实验以固定 Top-10 为基线。历史探索和冻结验证分开报告。冻结动作表有 943 行、来自 5 个 LoCoMo 对话；开发对话为 8、9、0，验证对话为 1、7，每个对话预留 24 条 onboarding，最终验证为 296 条。五个对话均曾在方法开发中被观察，因此这是冻结拆分回放，而非全新独立测试集。

| 指标 | 含义 | 使用边界 |
|---|---|---|
| 答案 Token F1 | 预测答案与参考答案词元重合的精确率、召回率调和平均 | 衡量答案文本匹配，不是语义质量全貌 |
| 答案词元召回率 | 参考答案词元被预测答案覆盖的比例 | 原代码字段为 `token_recall`；不是检索证据召回率 |
| 记忆上下文 token | 提供给答案生成的记忆文本长度 | 不等于包含提示词、输出、抽取和重试的 API 总消耗 |
| 官方 resolved | SWE 官方测试协议中的任务解决结果 | 与公开复现成功、脚本生成校验和补丁可应用分别报告 |
| 机制测试 | 单元测试、合成晋升回放、离线重算 | 证明相应机制能执行，不证明真实任务收益 |

最终自包含回放从缓存动作表重新计算决策和指标，不调用模型。它不重跑数据抽取、候选检索和答案生成；完整复现实验还需数据版本与动作表生成链路。

## 四、长对话实验结果

下表差值均为候选减去 Top-10；token 负值表示节省。不同实验样本不可合并计算总体收益。

| 实验 | 样本范围 | Δ F1 | Δ 答案召回率 | Δ 上下文 token/题 | 结论 |
|---|---|---:|---:|---:|---|
| 历史 adaptive KNN24 回放 | 923 条历史评估问题 | +0.02781 | +0.03952 | -63.57 | 历史探索中出现质量和成本同时改善；约节省 23.28% |
| 冻结 KNN24，置信系数 0 | 296 条验证问题 | -0.005196 | -0.030267 | -50.5912 | 约节省 19.35%，质量下降，未满足晋升目标 |
| LongMemEval ridge gate | 30 条缓存问题 | 0 | 0 | -22.90 | 仅 4 条选择 Top-5；小样本域内候选，不能直接迁移 |

本次重新执行冻结 runner，与仓库结果文件 SHA256 完全一致。冻结候选的 query-paired bootstrap 95% 区间为：F1 差值 [-0.03151, 0.02089]，答案召回率差值 [-0.06560, 0.00493]，上下文 token 差值 [-56.63, -44.62]。质量差值区间包含零不能证明质量不下降；只有两个验证对话也限制了跨对话推断。

LongMemEval 的 token 差值区间记录为 [-46.37, -3.53]。该结果来自此前缓存实验，本次未重新调用模型复测。

### 扩展算法与 L2/L3

历史 100 题答案实验中，原 adaptive F1 为 0.17946，真实 L2 为 0.17034，L2+L3 为 0.16640；完整构建成本为 331,316 token。当前证据不支持默认加入真实高层记忆来提升综合性价比。

30 题统一缓存比较中，MLP raw 的 F1 差值为 -0.02984、token 增加 332/题；离线 Q 的 F1 点增益 +0.00580 伴随答案召回率下降 -0.01334。加入双质量门后均退回 Top-10。source-neighbor 是增量辅助组织代理，不应称作新的真实 L2/L3 抽取结果。

这些实验说明，在当前数据规模下增加模型复杂度并未带来稳定优势。后续优先增加独立配对反馈，而不是继续在已观察的小样本上调整算法。

## 五、编程实验与失败分析

| 历史五题实验 | 脚本生成校验 | 生成补丁有效 | 官方 resolved | API 总 token |
|---|---:|---:|---:|---:|
| public reproduction | 5/5 | 4/5 | 1/5 | 114,384 |
| reproduction + repair | 5/5 | 4/5 | 1/5 | 148,010 |

“脚本生成校验通过”不代表成功复现目标故障。原始日志中，Astropy-13236 出现导入错误，14365 出现测试输入使用错误，repair 组的 14369 在基座上已通过且生成补丁无效。应按任务审核有效复现，不能继续使用“5/5 有效复现”这一结论。

低解决率不能仅归因于模型能力。已观察到的原因同时包括错误运行环境/API 假设、复现脚本自身错误、关联源码覆盖不足、补丁生成失败，以及修复引入的新回归。增加修复轮次还会显著增加费用。公开 probe 成功也不等于官方 resolved。

后续工具改进针对这些可观察故障，但目前没有足够的独立、同配置配对证据证明记忆策略稳定提升 SWE 解决率。历史总结记录的真实编程契约反馈只有 2 条，尚不足以满足 24 条起始门槛，也不构成充分学习样本。

## 六、实现验证与交付边界

2026-09-14 在独立解压并安装依赖的候选包上，31 项 TypeScript 测试、14 项 Python unittest、项目构建、冻结回放和 25 条合成晋升回放均通过。验收结果与运行环境记录在 results/final-verification.json，最终交付包的独立验收记录见 docs/topic3c/CLEANROOM.md。单元测试和 mock 存储边界的集成测试不替代真实部署、模型调用或 SWE 官方测试。

本次交付内容为：

1. 方案代码：策略、自动召回接入、编程反馈、晋升/回退和编程实验适配器。
2. 测试代码：组件单元测试、召回入口回归测试、合成 smoke、冻结公开长对话回放。
3. 本报告、固定版本及数据清单、实验配置、运行说明、最终包校验值。

打包读取 clean 工作区的已跟踪文件和显式审阅的新文件，逐文件记录 SHA256，避免旧 HEAD 源码与新报告混用。Markdown 是本报告的唯一正文来源，PDF 由同目录渲染器生成。关闭策略不改变基座静态 K；状态文件改为完整作用域的 SHA256 名称，旧的截断文件名状态不自动迁移，而重新开始 onboarding，避免沿用可能冲突的学习状态。

依赖审计另报告 24 项告警（22 moderate、2 high），high 涉及上游 OpenTelemetry 依赖链；本次没有批量升级基座遥测依赖。功能验收通过不等于依赖安全审计通过，具体状态见 CLEANROOM.md。

## 七、结论

本项目建立了有界检索动作、受控反馈更新和候选质量约束的实现框架，并提供公开长对话决策回放及编程反馈适配。历史实验呈现了按查询节省上下文的潜力，但冻结验证没有同时守住答案质量与召回率，编程实验也尚未证明稳定的任务解决率收益。

因此，当前建议保留基座路径作为默认，将候选策略用于受控影子评估。入口回退与门控接入已完成，下一阶段需要用新的独立任务验证质量和完整成本。当前最可信的贡献是可审查的实现、可重算的对照和明确的失败边界，而不是宣称已经实现通用的低成本高召回策略。
